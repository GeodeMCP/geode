Connect

Connect your vault to an AI client

Two ways to plug in an MCP client — these are alternatives, so pick the one that matches where your AI runs.

Add with a config (JSON)

For clients on this machine — Claude Code, Claude Desktop and other local MCP clients reach this kernel directly.

Works now
mcp.json 
{
  "mcpServers": {
    "geode": {
      "type": "http",
      "url": "http://localhost:8794/mcp",
      "headers": {
        "Authorization": "Bearer ••••••••••••••••"  // 
      }
    }
  }
}
…or one line in Claude Code
terminal
$ claude mcp add --transport http geode \
    http://localhost:8794/mcp \
    --header "Authorization: Bearer ••••••••"
This is your kernel's bearer token — anyone with it can use your vault. It's shown only inside this signed-in dashboard. Cloud clients (claude.ai, mobile) can't reach localhost — for those, use the URL option below.
or

Add with a URL

Paste one URL into Claude and sign in — no token to copy. Works from any Claude client, including claude.ai and mobile.

Setup required
https://<your-vault>.geodemcp.com/mcp
  1. In Claude → Settings → Connectors → Add custom connector
  2. Paste the URL above and click Add
  3. Click Connect and sign in to authorize Geode (OAuth)
A public URL + sign-in connector aren't enabled yet. Turn on a tunnel to activate this.
What it does

Your AI works against your vault

Geode speaks the Model Context Protocol (MCP). Once a client is connected, it gains the tools below and works directly against your context vault — read it, add to it, and run integrations on your behalf.

Tools a connected client can call
query

Ask your vault. It searches your context, recipes and SOPs and returns a synthesized answer — or an executable plan (the exact invoke calls to run).

instruction string
remember

Save a distilled learning, fact or note. The vault agent integrates it, dedups against what's there, and files it in the right place.

content stringsource string?title string?
list_capabilities

List what your vault offers — recipes / skills and integrations with their actions. Cheap; a client calls this to learn what the vault can do.

no parameters
invoke

Run one action of an integration — the client executes it; the kernel injects the required secret server-side, so the secret never reaches the AI.

integration stringaction stringparams object?
Secrets stay server-side. The agent never reads them and never calls integrations itself — it returns a plan, your client runs invoke, and the kernel injects the secret into the outbound request.
